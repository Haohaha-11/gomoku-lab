# 五子棋创新功能实施方案

本方案把强化学习、人类反馈和搜索深度放在同一个可检验框架中。当前版本已实现 Python 极大极小与 Alpha-Beta 搜索、棋盘与深度对照实验、可操作的网页演示、带时间预算的迭代加深，以及反馈保存接口。反馈记录落子前棋盘、AI 候选、正负评价与可选替代落子，不触发训练。强化学习训练和人类偏好训练属于后续计划；没有模型检查点、训练日志和独立测试结果时，不把它们标记为已完成，也不预先宣称能够拿满创新分。

## 一 先明确研究问题

1. 在相同单步推理预算下，自我对弈学到的局面价值能否提高 Alpha-Beta 的棋力？
2. 人类反馈能否改善落子偏好或明显失误率，同时保留客观胜负表现？
3. 在相同平均计算预算下，按局面分配深度能否比固定深度取得更好的胜率与延迟平衡？

课程要求的 Minimax 与 Alpha-Beta 对照继续单独保留。不能将更窄的候选集合、更短的搜索、不同的估值函数带来的差异误写成剪枝收益。

## 二 分阶段交付

| 阶段 | 可展示内容 | 完成证据 | 预计资源上限 |
| --- | --- | --- | --- |
| 基础版 已实现 | 两种搜索、迭代加深、主要变化线、逐步统计、反馈保存 | 源码、测试、CSV、网页 | CPU；可直接验收 |
| 深度实验扩展 计划 | 节点预算、按局面自适应停止、固定预算棋力评估 | 固定预算对局和 p95 延迟报告 | 先做 100 局配对测试 |
| 学习评估原型 | 小棋盘自我对弈，价值网络替换叶节点评分 | 数据清单、训练曲线、冻结检查点 | 首轮 2,000 局，每个种子最多 2 CPU 小时 |
| 人类反馈原型 | 同一局面两候选选择，离线偏好模型 | 200 到 500 条有效偏好、分组测试 | 3 名成员分别采集，保留分歧 |
| 完整创新评估 | 搜索、学习、反馈、深度各模块消融 | 多种子独立测试与失败案例 | 小规模通过后再扩容 |

以上是工作量预算和停止条件，不是已取得的耗时或样本量。先测 hk_88 的实际 CPU 吞吐；没有 GPU 时采用小网络和小棋盘。训练进程与演示服务隔离，限定线程数；超出预算则缩小训练轮次并如实记录。

## 三 强化学习怎样接入

采用 9×9 自由规则五子棋起步。环境输出当前执子方棋子、对方棋子、合法位置三个通道；终局胜、负、和的回报分别为 1、−1、0。每次切换执子方后同步翻转价值符号。非法动作由掩码排除，终局不继续采样动作。保留现有胜负检测与合法性测试作为唯一规则来源。

第一阶段用小型卷积价值网络，约 3 层卷积、每层 32 通道，输出范围限制到 [−1,1]。从自我对弈轨迹中保存局面与最终胜负，用回归损失学习当前执子方的终局回报。行动策略使用带少量探索的现有搜索；对手池混入历史模型和固定启发式对手，避免只适应最新自己。这是基于自我对弈回报的价值学习原型；单纯拟合启发式分数或模仿教师落子应另标为监督预训练。

第二阶段可增加策略头，在自我对弈中用终局回报与价值基线进行策略梯度更新，并保留熵正则与合法动作掩码。若加入 MCTS，则把搜索访问次数作为策略训练目标，明确这是更换搜索框架后的扩展实验，不纳入原始 Minimax 与 Alpha-Beta 公平性比较。这个方向参考 AlphaZero 的自我对弈与搜索结合思想，课程原型的模型、算力和棋盘规模都远小于论文系统，不能称为复现 AlphaZero。[Silver 等 2017](https://arxiv.org/abs/1712.01815)

价值网络接入 Alpha-Beta 的截断叶节点；策略头优先用于排序。为区分排序和选择性裁剪的影响，保留两种模式：只改变遍历顺序而不丢候选，以及固定 top-k 候选模式。终局胜负仍以规则引擎为准，模型输出不能覆盖确定的成五结果。

## 四 人类反馈怎样接入

网页反馈以同一局面的一对合法候选为单位。参与者选择 A、B、相当或无法判断，可标记“进攻”“防守”“可解释性”等原因。A/B 顺序随机，隐藏算法名称；至少 20% 的样本重复或交叉分配给另一位成员，用于估计一致性。收集前保存原始棋盘、当前执子方、两候选、评分版本、搜索预算、匿名标注者编号和时间。点赞只作为反馈入口，单个点赞并不构成完整的偏好训练数据。

先训练轻量的成对偏好模型：用两个候选落子后局面的分差预测 A 优于 B 的概率，以交叉熵拟合标签。相当可记为 0.5，无法判断不参与损失。初始可以只学习棋型特征的线性权重，样本充足后再尝试小网络。该设计参考基于成对人类偏好的奖励学习，但用途收窄为五子棋落子偏好校准。[Christiano 等 2017](https://arxiv.org/abs/1706.03741)

部署时将客观胜负价值与偏好分分别归一化，偏好权重从 0 开始，只在验证集选择。对已有一步必胜或必须防守的局面，规则安全层优先。若加入偏好奖励后独立对局胜率下降或一步漏防增加，则减小权重或仅用于相同价值候选之间的排序。只有偏好模型实际更新并经独立测试后，才称为“人类反馈学习”；收集按钮和 JSON 日志本身不等于 RLHF。

## 五 深度与计算预算怎样设计

当前课程基准设置固定目标深度，深度按半回合计数，即一个棋手的一次落子算一层。搜索已采用从 1 到目标深度的迭代加深，仅提交最后一轮完整搜索的落子和主要变化线。在线界面显示请求深度、实际完成深度、节点数、剪枝次数和耗时；离线算法对照关闭超时并完成目标深度，统计累加所有迭代轮次。

自适应版本设置节点预算和墙钟上限，在候选首位分差小、存在双威胁或上一层主变化线改变时继续加深；当预算耗尽时返回完整轮结果。阈值只在验证集选择。与固定深度相比时必须报告每步平均节点数和 p95 耗时，不能只展示胜率。搜索预算未完成的局面单独计数，不混入完整深度的算法等价性统计。

训练课程可以从 9×9、浅层对手逐步过渡到更深对手，再迁移到 13×13 或 15×15。每个阶段都保留上一阶段测试；扩大棋盘会改变分布，不能直接把 9×9 的胜率当作 15×15 的结果。

## 六 数据拆分与可复现性

- 固定独立种子 7、23、61，分别控制 Python、NumPy、训练框架与自我对弈采样；记录软件版本、线程数、网络配置和检查点哈希。
- 按完整对局和开局族划分 70% 训练、15% 验证、15% 测试。同局面旋转与镜像的规范化哈希用于跨集去重；同一条对局的相邻局面不得跨集。
- 自我对弈只使用训练开局；验证集用于选择混合权重、早停与深度阈值；测试集一次冻结，禁止训练或选择检查点时读取胜率。
- 人类偏好数据按局面族分组划分，并补充按标注者留出的评估；同一对候选交换 A/B 后仍属于同一数据组。
- 张量维度、dtype、合法动作数量、价值范围和 NaN 检查必须保留；检查点加载失败时回退到明确标注的启发式搜索。

## 七 对照实验与验收标准

| 对照 | 保持一致 | 要回答的问题 |
| --- | --- | --- |
| Minimax 对 Alpha-Beta | 同局面、深度、估值、候选与排序 | 剪枝节省多少节点，根值是否一致 |
| 启发式对学习价值 | 相同候选与单步预算 | 学习是否提升棋力 |
| 无反馈对有反馈 | 同一个基础检查点与搜索预算 | 偏好收益是否伴随胜率损失 |
| 固定深度对自适应深度 | 平均节点预算与最大耗时 | 计算分配是否更有效 |
| 仅排序对 top-k 裁剪 | 估值与局面一致 | 加速来自顺序还是牺牲搜索范围 |

建议每个种子至少 50 个固定开局、每个开局互换先后手，共 100 局。首轮 3 个种子合计每个对照 300 局；若置信区间太宽则按预算扩展。报告胜率、平局率、胜平半分得分率、95% 置信区间、单步中位数与 p95 延迟、平均节点数、一步漏防率、完成深度分布。对局共享开局会相关，优先按开局分组自助法估计区间，不把所有落子当独立样本。

偏好模型报告独立测试准确率、交叉熵与标注一致性；平票与无法判断占比也应公开。消融至少包括基础搜索、仅学习价值、仅偏好排序、仅自适应深度、完整组合。保留输棋和意见分歧案例，不只挑选成功展示。

## 八 演示顺序与风险

建议验收先演示合法落子、成五和重新开始；在同一中盘局面切换 Minimax 与 Alpha-Beta，解释相同评分下节点数的变化；再改变深度和棋盘大小查看真实数据。创新部分展示反馈入口、可复现的数据格式与实施路线，训练尚未完成时直接标注计划中。

主要风险是浅层搜索的视野效应、top-k 候选漏掉关键防守、自我对弈退化、人类偏好分歧、奖励尺度冲突、服务端 CPU 竞争，以及漂亮界面掩盖不稳定算法。对应处理是战术测试集、全候选小棋盘核对、历史对手池、独立标注一致性检查、保留客观胜负约束、限制训练资源，以及把准确性测试与视觉演示分开验收。
