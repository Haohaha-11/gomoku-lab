## 0. 结论先行

**一句话叙事：把 Alpha-Beta 拆成三个部件，三个创新点各改进一个部件。**

| Alpha-Beta 的部件 | 对应创新方向 | 具体做法 | 拿分证据 |
|---|---|---|---|
| 搜索控制：能搜多深 | 博弈树深度 | 增量评估 + 迭代加深 + 置换表 + 启发式排序 + VCF/VCT 威胁空间搜索 | 同等时间下的可达深度、节点数、排序效率相对理论最优的比例 |
| 叶节点评估：看得准不准 | 强化学习 | TDLeaf(λ) 自我对弈学习棋型特征权重 | 学习曲线、Elo、权重演化、跨棋盘大小迁移 |
| 目标与偏好：像不像人、好不好玩 | 人类反馈 | 两两偏好 → Bradley–Terry 奖励模型 + 锚定正则；自适应难度 | 偏好预测准确率、人类走法预测准确率、人类胜率与难度评价 |

**为什么这样设计能拿分：**

1. **紧扣实验主题。** PPT 要求分析"两种算法性能、棋盘格大小、搜索深度"。三个创新点都在加深这个主题，而不是另外接一个和博弈搜索无关的神经网络。
2. **每个点都有可量化的对照实验**，不只是"多做了一个功能"。
3. **全部能在 CPU 上完成。** hk_88 是 8 核、7.8 GB 内存、没有 GPU；本机 RTX 4050 只用于可选的 P2。
4. **人类反馈数据来源是现成的。** PPT 第 3 页要求"实验结果的小组相互体验和评价"：其他组来玩我们的 demo，就是在给我们标注数据。

**对当前假设的修正：** `.agent/coverage.md` 写的是"RL 这轮只做规划"。建议改为**真正训练** TDLeaf(λ) 线性评估：计算量小（见 3.2），只交规划拿不到多少创新分。AlphaZero 式神经网络才放到"规划/可选"。

## 1. 统一框架：同一套特征，三种权重来源

评估函数：

```
V(s) = tanh( w · φ(s) / T )        # 输出 ∈ (-1, 1)，以轮到走棋的一方为视角（negamax）
```

**特征 φ(s)：棋型计数，己方和对方各一份**

| 类别 | 特征 |
|---|---|
| 基本棋型 | 连五、活四、冲四、活三、眠三、活二、眠二 |
| 复合棋型 | 双活三、冲四活三、双冲四 |
| 其他 | 先手标志（1 维） |

合计约 2 × 10 + 1 = 21 维。

> 关键性质：特征只依赖局部棋型，**与棋盘大小无关**。因此 9×9 上学到的权重可以直接用在 15×15 上，这正好对应 PPT 的"棋盘大小"分析，可以单独做一个迁移实验（E-R3）。

**三组权重：**

| 权重 | 来源 | 类比 LLM 流程 |
|---|---|---|
| `w_hand` | 手工设定（基础版本） | 规则系统 |
| `w_RL` | TDLeaf(λ) 自我对弈学出 | 预训练 / 自我提升 |
| `w_HF` | 在 `w_RL` 基础上用人类偏好微调 | RLHF |

答辩时可以直接说"我们在五子棋上复刻了一遍 预训练 → RLHF 的流程"，评委容易理解。

**飞轮：**

```
 自我对弈 (RL) ──► w_RL ──► 人机对弈 + 偏好投票 (HF) ──► w_HF
      ▲                                              │
      │                                              ▼
 更强/更像人的 AI ◄── 搜得更深 ◄── 评估更准 + 排序更好（剪枝更多）
```

## 2. 创新一：博弈树深度

### 2.1 技术清单（每一项都可以单独消融）

| 编号 | 技术 | 作用 | 优先级 |
|---|---|---|---|
| D1 | 增量评估：落子后只重算经过该点的 4 条线 | 每秒搜索节点数（NPS）成倍提升，是后面所有实验的基础 | P0 |
| D2 | 候选生成 + 威胁优先静态排序（成五 > 挡五 > 活四 > 挡四 > 冲四活三 > 活三 …） | 好的排序是剪枝的前提 | P0 |
| D3 | 迭代加深 + 时间控制，上一轮主变例着法优先 | 任意时刻都能给出着法，可按时间预算比较 | P0 |
| D4 | Zobrist 哈希置换表（EXACT / LOWER / UPPER） | 复用转置局面 | P0 |
| D5 | 杀手着法（每层 2 个）+ 历史启发 | 动态排序 | P0 |
| D6 | PVS 零窗口搜索 + 渴望窗口 | 进一步减少节点 | P1 |
| D7 | **VCF 搜索（连续冲四）**：进攻方只走冲四/成五，防守方只有唯一应手 | 分支因子约为 1，可以搜 20 层以上；demo 的"绝杀"演出靠它 | P0 |
| D8 | VCT 搜索（活三 + 冲四） | 更强的强制胜搜索 | P1 |
| D9 | 威胁延伸：叶节点存在冲四时再多搜 1 层（类似国际象棋的静态搜索） | 缓解水平线效应 | P1 |

### 2.2 实验

| 编号 | 实验 | 设置 | 图表 |
|---|---|---|---|
| E-D1 | 节点数随深度的变化 | 15×15，固定 30 个中局局面；Minimax / AB / AB+排序 / AB+TT+迭代加深 / +PVS；深度 1–6（Minimax 到 4 即可） | 对数坐标折线图 |
| E-D2 | **排序效率** | 理论最小树（Knuth–Moore）的叶子数为 `b^⌈d/2⌉ + b^⌊d/2⌋ − 1`（b 取平均候选数）。计算"实测节点数 / 理论最小值"，以及首着截断率（fail-high 发生在第一个着法上的比例，好的引擎 > 90%） | 柱状图：各排序方案离"完美排序"还差多少 |

## 3. 创新二：强化学习，TDLeaf(λ)

### 3.1 方法

TDLeaf(λ) 是 KnightCap 国际象棋程序使用的方法（Baxter、Tridgell、Weaver，1998）：用 TD 学习调整 Alpha-Beta 的评估函数，但学习目标取**搜索后主变例叶子**的值，而不是根节点的值。这样学到的评估与搜索本身是匹配的，和本实验的结合非常自然。

1. **自我对弈**：双方都用当前权重 w，以深度 d = 2 的 AB 搜索走棋。前 2–4 手随机开局，并加 ε-greedy（ε 逐步衰减）保证探索。
2. **记录**：每一步记录主变例叶子 `l_t` 的特征 `φ(l_t)`，令 `V_t = tanh(w·φ(l_t)/T)`。
3. **时间差分**：`d_t = V_{t+1} − V_t`，注意 negamax 视角翻转（对手视角的值要取负）。终局时胜/负/和分别取 +1 / −1 / 0。
4. **更新**：`w ← w + α · Σ_t ∇_w V_t · Σ_{j≥t} λ^{j−t} d_j`，λ ≈ 0.7，α 逐步衰减。
5. **两种初始化**：
   - 全零初始化：展示"从零学会下棋"，体现 RL 本身；
   - `w_hand` 初始化：微调，追求最强。
6. **训练棋盘**：9×9 或 11×11（快）；在 15×15 上评测（迁移）。

### 3.2 计算量估算（以实测为准）

- 深度 2、候选上限 K = 15、增量评估：每步约 225 个叶子，纯 Python 估计 10–50 ms/步；一局约 40 步，即 1–2 s/局。
- hk_88 跑 6 个进程（留出内存给 web 服务）：每小时大约几千到上万局。21 维线性模型通常几千局就会收敛。
- 如果纯 Python 太慢，评估函数用 numba 加速（本机已装 numba 0.63）。
- 并行方式：多个 actor 进程自我对弈产出轨迹，主进程批量更新（同步 actor/learner，实现简单）。

### 3.3 实验

| 编号 | 实验 | 图表 |
|---|---|---|
| E-R1 | 学习曲线：每 200 局保存一个 checkpoint，与 `w_hand` 对弈 100 局（交换先后手） | 胜率 / Elo 随训练局数变化 |
| E-R2 | 权重演化 | 各棋型权重随训练变化。可解释性亮点：看 RL 是否自己"发现"活三 > 眠三、冲四活三 ≈ 必胜 |
| E-R3 | 跨棋盘迁移：9×9 学到的权重在 15×15 上对 `w_hand` 的胜率 | 柱状图 |
| E-R4 | 消融：零初始化 vs 手工初始化；λ = 0 / 0.7 / 1.0 | 表格 |

### 3.4 【P2】AlphaZero 式小网络（可选）

- 小 ResNet（6 个残差块，64 通道）策略-价值网络，9×9 棋盘，本机 RTX 4050 训练。
- **不替代 AB，而是作为 AB 的走法排序先验**：用策略网络的输出给候选排序，再测 E-D2 的排序效率提升。这样又回到了"博弈树深度"这个主题。
- 风险：Python 实现的 MCTS 自我对弈很慢。建议先用 AB 引擎的对局做监督预训练（蒸馏），再做自我对弈微调。
- 时间不够就只写进报告"展望"，不要塞半成品。

## 4. 创新三：人类反馈

### 4.1 数据采集（内置在 web demo 中）

| 编号 | 反馈类型 | 交互方式 |
|---|---|---|
| F1 | 对局日志 | 每局人机对弈的每一步：局面、人类落子、AI 候选及分数、用时、胜负结果 |
| F2 | **两两偏好："AI 犹豫了"** | 只在 AI 前两名候选分差很小的局面弹出（主动学习：只问模型最不确定的问题）。棋盘上显示 A / B 两颗幽灵棋子，让人选"哪步更好 / 差不多"。做成小游戏：投票计分 + 排行榜 |
| F3 | 局后评价 | 难度（太简单 / 刚好 / 太难）、乐趣 1–5 分 |

- **采集时机**：demo 部署后尽早把 URL 发给同学；课堂"小组相互体验和评价"环节现场采集（8 组约 24 人）。
- **存储**：hk_88 上的 SQLite（`feedback.db`）。只用匿名昵称，不收集个人信息。

### 4.2 奖励模型与对齐（RLHF 的线性版本）

- **Bradley–Terry 偏好模型**：

  ```
  P(A ≻ B) = σ( w · (φ(s_A) − φ(s_B)) )
  ```

  其中 `s_A`、`s_B` 是分别落子 A、B 之后再做浅层搜索（d = 2）得到的叶子局面，用来稳定评估。

- **损失函数**：

  ```
  L(w) = −Σ log σ(...)  +  μ · ‖w − w_RL‖²
  ```

  μ 项对应 RLHF 中的 KL 约束：防止为了迎合人类偏好而丢掉棋力。答辩时可以重点讲这个对应关系。

- **人类走法预测（行为克隆）**：条件 logit 模型 `P(m | s) ∝ exp( w·φ(s 落子 m 之后) / τ )`，用 F1 数据拟合。

- **小样本的现实情况**：几百条偏好只用来拟合约 21 维的线性权重，统计上可行。所有指标都报 bootstrap 置信区间。

### 4.3 反馈的三种用途

1. **"人类对齐"风格引擎 `w_HF`**：在 demo 中可以切换。
2. **自适应难度（DDA）**：在线估计玩家的 Elo，映射到"搜索深度 / 时间预算 + 根节点 softmax 温度 τ"，目标是让人类胜率保持在 40–50%。**这是"人类反馈"和"博弈树深度"的直接连接：搜索深度就是难度旋钮。**
3. **AI 复盘**：局后指出人类胜率下降最多的一步，给出更优着法和理由（例如"此后白方存在 7 步 VCF"）。这是反方向的 AI → 人反馈，能提升同学互评时的体验分。

### 4.4 实验

| 编号 | 实验 | 说明 |
|---|---|---|
| E-H0 | **合成数据验证（先做，不依赖真人）** | 设定一个已知的"老师"权重 `w*`（例如偏进攻），用它生成模拟偏好，检验 BT 拟合能否恢复 `w*`（余弦相似度随样本数的曲线）。既证明方法正确，也是真人数据不够时的保底 |
| E-H1 | 偏好预测准确率（留出 20%） | 比较 `w_hand` / `w_RL` / `w_HF` |
| E-H2 | 人类走法预测准确率 | top-1 / top-3 |
| E-H3 | 棋力保持 | `w_HF` 对 `w_RL` 对弈，取不同 μ，画出"棋力–对齐"权衡曲线（对应 RLHF 的 reward–KL 曲线） |
| E-H4 | 自适应难度的效果 | 固定难度 vs 自适应：人类胜率分布、"刚好"评价的比例（样本小，以定性结论 + 置信区间为主） |

## 5. 统一评测协议

- **选手表**：`M-d3`（Minimax）、`AB-d4`、`AB+`（D1–D5）、`AB++`（再加 VCF）、`RL`（w_RL）、`HF`（w_HF），以及可选的 `NN-ordering`。
- **循环赛**：每对选手 100 局，先后手各 50 局。开局从固定随机种子生成的 50 个平衡开局（中心附近 3 子）中抽取，避免确定性引擎反复下同一局。
- **计时**：主实验每步 1 s；固定深度作为对照。
- **Elo**：Bradley–Terry 最大似然估计 + bootstrap 95% 置信区间。
- **数据同源**：原始数据全部写入 `results/*.jsonl`，图表由脚本生成；报告和网页读同一份数据。
- **规则说明**：自由五子棋（无禁手）在 15×15 上已被证明先手必胜（Allis，1994），所以所有对比都必须交换先后手，报告中写明规则。

## 7. 接口约定（与主体代码对齐）

```python
class Evaluator(Protocol):
    def features(self, board, player) -> np.ndarray: ...  # 与棋盘大小无关的棋型计数
    def evaluate(self, board, player) -> float: ...

@dataclass
class SearchResult:
    best_move: tuple[int, int]
    score: float
    pv: list[tuple[int, int]]
    depth_reached: int
    nodes: int
    cutoffs: int
    tt_hits: int
    time_ms: float
    root_scores: list[tuple[tuple[int, int], float]]  # 热力图 + 偏好候选
    forced_win: list[tuple[int, int]] | None          # VCF/VCT 序列
    leaf_features: np.ndarray | None                  # TDLeaf 需要的主变例叶子特征
```

- **权重文件**：`weights/hand.json`、`weights/tdleaf.json`、`weights/hf.json`。每个文件带 meta：训练局数、日期、代码版本。
- **反馈 API**：`POST /api/feedback/preference`、`POST /api/feedback/rating`、`POST /api/game/log`、`GET /api/feedback/stats`。
- **建议目录**：`gomoku/search/`、`gomoku/learn/tdleaf.py`、`gomoku/learn/preference.py`、`scripts/train_tdleaf.py`、`scripts/fit_preferences.py`、`scripts/tournament.py`。

## 9. 报告"创新与拓展"章节

- 每个创新点按"动机 → 方法 → 实验设置 → 结果 → 局限"写。
- 明确区分**已实现 / 已训练 / 规划中**三种状态；人类数据的样本量如实写出。
- **答辩 30 秒话术**："Alpha-Beta 由三部分组成：搜索控制、叶节点评估和目标。我们用置换表、启发式排序和 VCF 让它在同样时间内多搜 X 层；用 TDLeaf 强化学习让它自己学会评估，胜率从 50% 提升到 Y%；再用同学们的 N 条偏好投票做了一个线性版的 RLHF，并用人类反馈自动调节搜索深度，让对局难度刚好。"
